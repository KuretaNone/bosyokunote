以下の仕様のアプリをGo言語で作成して

## 画像管理するソフトを作りたい

- アプリ名Media File Sort Tool(mfst.exe)
- 64bitアプリケーション
- 設定ファイル`%LocalAppData%\mfst\setting.yaml`
- ログファイル`%LocalAppData%\mfst\logs\`

## 設定ファイルについて
`Extension`分類する拡張子
`Path`自動で仕分けするファイルの拡張子
`FolderName`Path以降の自動で生成フォルダの名前。変数利用可能
`FileName`空の場合はリネームしない。変数利用可能

### 変数について
- `<yyyy>` 年(4桁)
- `<yy>` 年(2桁)
- `<mm>` 月(2桁)
- `<dd>` 日(2桁)
- `<hh>` 時(2桁)
- `<mi>` 分(2桁)
- `<ss>` 秒(2桁)
- `<rn01>` 連番1桁
- `<rn02>` 連番2桁
- `<rn03>` 連番3桁
- `<rn04>` 連番4桁
- `<original_name>` 元のファイル名(拡張子なし)
- `<ext>` 拡張子
- `<hash8>` ファイルハッシュ(SHA256の最初の8文字)

```yaml
# 全般設定
General:
  DryRun: false  # true: テスト実行モード(実際にはコピー・削除しない)
  CreateBackup: true  # 削除前にバックアップを作成
  BackupPath: "%LocalAppData%\\mfst\\backup"
  LogLevel: "Info"  # Debug/Info/Warning/Error
  VerifyAfterCopy: true  # コピー後にチェックサム検証
  DeleteAfterVerify: true  # 検証成功後に元ファイルを削除
  ShowProgress: true  # TUIモード時のプログレスバー表示
  MaxConcurrent: 1  # 並列処理数(1=安全優先)

# 重複ファイル処理
DuplicateHandling:
  Strategy: "rename"  # skip/rename/overwrite/ask
  RenamePattern: "-{nnn}"  # 重複時の連番パターン(3桁)
  CompareByHash: true  # ハッシュ値で同一ファイルを判定

# Exif/メタデータ設定
Metadata:
  # 使用するExifタグの優先順位(上から順に確認)
  DateTimeTags:
    - "DateTimeOriginal"  # 撮影日時
    - "CreateDate"
    - "DateTimeDigitized"
    - "ModifyDate"
  # Exif取得失敗時のフォールバック
  FallbackToFileSystem: true
  # ファイルシステム日時の優先順位
  FileSystemDatePriority:
    - "CreationTime"  # 作成日時
    - "LastWriteTime"  # 最終更新日時
  # タイムゾーン処理
  AssumeLocalTimeZone: true

# 画像の設定
Image:
  Extension:
    - jpeg
    - jpg
    - png
    - gif
    - bmp
    - webp
    - svg
    - tiff
    - tif
    - heic
    - heif
    - raw
    - cr2
    - nef
    - arw
  Path: "%USERPROFILE%\\Pictures\\Images"
  FolderName: "<yyyy>-<mm>"
  FileName: "<yyyy><mm><dd>"

# 動画の設定
Movie:
  Extension:
    - mp4
    - avi
    - mov
    - wmv
    - flv
    - mkv
    - webm
    - m4v
    - mpeg
    - mpg
    - 3gp
    - mts
    - m2ts
  Path: "%USERPROFILE%\\Pictures\\Movies"
  FolderName: "<yyyy>-<mm>"
  FileName: "<yyyy><mm><dd>"
```

## 仕分けについて

### 日時情報の取得優先順位
1. **Exif/メタデータ情報**
   - `Metadata.DateTimeTags`で指定された順序で取得を試みる
   - 取得できた最初の有効な日時を使用

2. **ファイルシステム情報**(Exif取得失敗時)
   - `Metadata.FileSystemDatePriority`で指定された順序で使用
   - デフォルト: 作成日時 → 最終更新日時

### 処理フロー
1. **対象ファイルのスキャン**
   - 指定ディレクトリ(サブディレクトリ含む)を走査
   - 除外設定に該当するファイル・ディレクトリをスキップ
   - ファイルサイズフィルタを適用

2. **日時情報の取得**
   - 上記優先順位に従って日時を取得
   - 取得した日時をログに記録

3. **移動先パスの生成**
   - `Path`ディレクトリ内に`FolderName`で指定されたサブディレクトリを生成
   - `FileName`が空でない場合、変数を展開してファイル名を生成
   - `FileName`が空の場合、元のファイル名を維持

4. **重複チェック**
   - 同名ファイルが存在する場合、`DuplicateHandling.Strategy`に従って処理
   - `CompareByHash: true`の場合、ハッシュ値を比較して同一ファイルかチェック

5. **ファイルのコピー**
   - `DryRun: false`の場合のみ実際にコピー
   - コピー中はプログレスバー表示(TUIモード時)

6. **検証**
   - `VerifyAfterCopy: true`の場合、コピー元とコピー先のハッシュ値を比較
   - 不一致の場合はエラーとして処理中断

7. **バックアップと削除**
   - `CreateBackup: true`の場合、元ファイルをバックアップディレクトリに移動
   - `DeleteAfterVerify: true`かつ検証成功の場合、元ファイルを削除
   - バックアップのみの場合、元ファイルは削除しない

8. **ログ記録**
   - 処理結果(成功/失敗/スキップ)をログファイルに記録

## ファイルは安全のため、検証してから削除する
- コピー後に必ずチェックサム(SHA256)で検証
- 検証失敗時は元ファイルを保持
- オプションでバックアップ作成可能
- 動作速度は遅くてもいいので、安全処理を優先する

## 使い方

### 基本コマンド
```
# 対話モード(TUI)で起動
mfst.exe

# 引数で指定されたディレクトリを整理
mfst.exe C:\Users\UserName\Downloads

# 複数ディレクトリを一括処理
mfst.exe C:\Dir1 C:\Dir2 C:\Dir3

# exeにファイルをドラッグ&ドロップ
# 渡されたファイル(or)ディレクトリを整理
```

### オプション
```
mfst.exe [OPTIONS] [DIRECTORY...]

OPTIONS:
  -h, --help              ヘルプを表示
  -v, --version           バージョン情報を表示
  -d, --dry-run           ドライラン(テスト実行)モード
  -c, --config <PATH>     設定ファイルのパスを指定
  -l, --log-level <LEVEL> ログレベル(Debug/Info/Warning/Error)
  -y, --yes               確認なしで実行
  --no-backup             バックアップを作成しない
  --no-verify             検証をスキップ(非推奨)
  --stats                 統計情報のみ表示(実行しない)
```

### 実行例
```
# ドライランで動作確認
mfst.exe --dry-run C:\Downloads

# バックアップなしで実行
mfst.exe --no-backup --yes C:\Downloads

# カスタム設定ファイルを使用
mfst.exe -c custom_setting.yaml C:\Downloads

# 統計情報のみ確認
mfst.exe --stats C:\Downloads
```

## エラーハンドリング

### 致命的エラー(処理中断)
- 検証失敗(ハッシュ値不一致)
- ディスク容量不足
- アクセス権限エラー
- 設定ファイル不正

### 警告(スキップして継続)
- Exif読み込み失敗(ファイルシステム日時で代替)
- 除外対象ファイル
- 既に同一ファイルが存在(ハッシュ一致)

### 回復可能エラー(リトライ)
- 一時的なファイルロック
- ネットワークドライブの接続不良
